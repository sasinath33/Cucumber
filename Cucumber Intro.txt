Chapter 1: Introduction to BDD and Cucumber

1.1 What is BDD?

- Behavior Driven Development (BDD) is a software development approach that encourages collaboration between developers, testers, and business stakeholders.

- It uses plain English descriptions of system behavior, making requirements easy to understand.

- BDD bridges the gap between technical and non-technical team members.

Key Benefits:

- Shared understanding of requirements.

- Automated acceptance tests.

- Living documentation.

---

1.2 Installing Cucumber with Maven

To use Cucumber in a Java project, we add dependencies in the pom.xml.

xml

<dependencies>

<!-- Cucumber Java -->

<dependency>

<groupId>io.cucumber</groupId>

<artifactId>cucumber-java</artifactId>

<version>7.11.2</version>

<scope>test</scope>

</dependency>

<!-- Cucumber JUnit -->

<dependency>

<groupId>io.cucumber</groupId>

<artifactId>cucumber-junit</artifactId>

<version>7.11.2</version>

<scope>test</scope>

</dependency>

<!-- Selenium (optional for UI testing) -->

<dependency>

<groupId>org.seleniumhq.selenium</groupId>

<artifactId>selenium-java</artifactId>

<version>4.8.0</version>

</dependency>

</dependencies>

Explanation:

- cucumber-java → Provides step definition support.

- cucumber-testng → Allows running Cucumber tests with testng.

- selenium-java → Used if we automate web applications.

1.3 Gherkin Syntax and Keywords

Gherkin is the language used to write Cucumber feature files. It’s simple and human-readable.

Common Keywords:

- Feature → Describes the functionality.

- Scenario → Defines a test case.

- Given → Precondition.

- When → Action.

- Then → Expected outcome.

- And / But → Additional steps.

---

1.4 Example: Login Feature File

gherkin

Feature: Login functionality

Scenario: Successful login with valid credentials

Given the user is on the login page

When the user enters valid username and password

Then the user should be redirected to the homepage

---

1.5 Step Definitions in Java

java

import io.cucumber.java.en.;

public class LoginSteps {

@Given("the user is on the login page")

public void userOnLoginPage() {

System.out.println("Navigating to login page...");

}

@When("the user enters valid username and password")

public void userEntersCredentials() {

System.out.println("Entering username and password...");

}

@Then("the user should be redirected to the homepage")

public void userRedirectedToHomepage() {

System.out.println("User is on homepage!");

}

}

1.6 Runner Class

java

import org.junit.runner.RunWith;

import io.cucumber.junit.Cucumber;

import io.cucumber.junit.CucumberOptions;

@RunWith(Cucumber.class)

@CucumberOptions(

features = "src/test/resources/features",

glue = {"stepDefinitions"},

plugin = {"pretty", "html:target/cucumber-report.html"}

)

public class TestRunner {

}

Explanation:

- features → Path to feature files.

- glue → Path to step definitions.

- plugin → Reporting options (HTML, JSON, etc.).

---

1.7 Quick Recap

- BDD makes requirements clear and testable.

- Cucumber integrates with Maven easily.

- Gherkin provides a readable way to write test cases.

- Step definitions connect plain English steps to Java code.

- Runner class executes the scenarios.
